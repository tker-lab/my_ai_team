部署ファイル(secretary.md記載の youtube_team.md / app_team.md / PR_team.md / life_team.md / advisory.md)は、セッション開始のたびに毎回読み込まれる設計のため、本体は簡潔に保つ。個別プロジェクトの内容が厚くなってきたら、`<部署名>_<プロジェクト名>.md`のような専用ファイルに詳細を切り出し、部署ファイル側には1〜2行の要約+リンクだけ残す。

**Why:** 部署ファイルが長文化すると、無関係な作業のときも毎回大量の情報を読み込むことになり非効率。一方で全部バラバラのファイルにすると部署の全体像が把握しづらくなる。「概要は1箇所、詳細は必要な時だけ開く別ファイル」のハイブリッドが両立する。既にstatus.mdが[[communication-plan-discord]]的な形でこのパターンを使っていたのが元ネタ。

**How to apply:** ある部署ファイル内の1トピックが数段落〜数十行を超えて厚くなってきたら、`<部署ファイル名(拡張子抜き)>_<トピック名>.md`を作り詳細を移す。部署ファイル側には「詳細は[ファイル名](ファイル名)参照」の1行を残す。2026-08-21、顧問部署のUSDA/AMSデータ取得プロジェクトで初適用(`my_ai_team/advisory_usda_project.md`)。CEOの指示により、今後**全部署でこの運用を標準とする**。

**2026-08-22:このルールはCLAUDE.mdの「その他の共通ルール」に格上げ済み(そちらが正典)。** 全部署共通=サブエージェントも読む必要があるため。このメモリは経緯の記録として残す。
