2026-09-15、字幕制作の自動化パイプラインを構築した。詳細な使い方は `~/my_ai_team/youtube_team_subtitle_workflow.md`、用語集は `~/my_ai_team/youtube_team_glossary.md`、スクリプト本体は `~/my_ai_team/tools/subtitle_pipeline/`(`transcribe_align.py` / `correct_and_wrap.py` / `glossary_lib.py`)。

**構成**:whisper.cpp(large-v3+VAD)で文字起こし → WhisperX(`jonatasgrosman/wav2vec2-large-xlsr-53-japanese`)で1文字ごとのタイムスタンプに補正 → 用語集(youtube_team_glossary.md)による誤字置換+うつのひらがな統一+フィラー削除 → BudouX(日本語分かち書き)で文節の塊を作り、2行以内・塊の途中で割らない形でSRT化。環境は `~/video_venv`(python3.12、`~/my_ai_team_venv`とは別)。

**技術的に分かったこと**:
- WhisperXは日本語で正常動作する(基本方針が事前に想定していた「断念してwhisper.cppの単語タイムスタンプで代替」は不要だった)。ただし稀に1セグメントだけアライメントに失敗する(`backtrack failed`。10分の音声中1回発生)。この場合`chars`が空になり、そのままだとタイムスタンプが0秒に落ちて字幕がずれるバグがあったため、`transcribe_align.py`側でセグメント区間に均等割りしたフォールバック時刻を補う実装にしてある(該当箇所はログに`WARNING: segment N had no char alignment`と出る)
- BudouXの塊分割は「という/ていただく/おります/指示語(この/その等)」のような機能語が単独の塊として孤立し、それをそのまま改行位置に使うと不自然な位置で割れる(例:「この/後紹介するんですけど」)。`correct_and_wrap.py`の`_merge_unsplittable()`で既知パターンを直前/直後の塊に強制結合する後処理を入れて対処したが、網羅的ではないため、初見の言い回しでは同種の不自然な改行が残り得る
- フィラー「まあ」は文中で句読点が直後に来ないことが多い(例:「まあそうやってですね」)。最初、句読点直前限定の正規表現にしていたら大量に取りこぼした→無条件マッチに修正した([[glossary_correction_notes]]参照、なければ今後作成)
- 通常のHomebrew `ffmpeg`formulaには字幕焼き込み(libass)が入っていない。焼き込みには別途`brew install ffmpeg-full`(keg-only、`/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg`)が必要
- Aegisubのbrew caskは2026-09-01付でGatekeeper非対応のため無効化されている(Apple公証未取得)。代替として署名・公証済みの`Subtitle Edit`(brew cask、Apple Silicon対応)を導入した

**2026-09-15夜〜16、チェック担当の指摘を受けた改善**:
- フィラー「あの」の判定にfugashi+UniDicフル辞書(`~/video_venv`に追加導入、unidic-liteでは精度不足だった)を導入し、品詞(連体詞/感動詞-フィラー)で指示語と区別する処理を追加。ただし**UniDic自身の品詞判定が文脈依存で割れることがあり(同じ「あの+名詞」パターンでも連体詞/フィラーの判定が変わる)、完全な自動判別はできないと実証的に確認した**。ヒューリスティック(フィラー判定でも直後が具体的な名詞なら残す。ただし「皆さん/次回/方/感じ/話/件/自分/軸/最後/まとめ」等の一般語は例外的に必ず削除)で3163の残存21件→6件まで改善。詳細は[[glossary_correction_notes]](未作成なら今後作成)
- BudouXの塊マージ規則を拡充:「なる」「ございま」「ところ」「わけ」「はず」「もの」「こと」等の形式名詞・機能語も直前の塊に吸収するようにし、「ありがとう/ございました」「〜になると/いうのは」のような連語の分断を解消
- 用語集に「ピンと来なくても(誤:ピントを来なくても)」を追加。**「1本目→1点目」は一度は用語集の自動置換表に入れたが、3163に「1本目の動画」という正しい用法が別途あり機械的な一括置換が壊すと判明したため撤回**。用語集の自動置換の表(正しい表記/読み方/誤認識例/補足)には「文脈によらず常に正しい」語だけを入れ、文脈で意味が変わる語は表以外の書き方(箇条書き)で「文脈判断が必要な語」として記録し、手順4で人が判断する運用に変更した。glossary_lib.pyのparse_glossaryは`|`で始まる行(表)しか読まないため、箇条書きにすれば自動置換の対象から確実に外せる
- 手順4(AIによる仕上げ)を3156で実地に実施し`3156_final.srt`を作成(94→91cue、手直し4箇所:文が不自然に分割されていた箇所の統合×2、孤立した続き言葉の統合×1、フィラー「あの」の目視除去×1)。手順4はスクリプトの後にClaudeが目視でガイドライン照合する工程として機能することを確認

**2026-09-16、チェック担当の再チェックで見つかった仕組み全体の問題と対応**:
- whisper.cppが**音声によっては句読点を一切打たないモードに入る**不具合を発見(3163で全編0個。3156では未発生で原因は特定できず)。句読点入り日本語文の`--prompt`+`--carry-initial-prompt`で再現しなくなることを確認し、`transcribe_align.py`にデフォルト組み込み済み。**新しい動画で文字起こし直後に読点・句点がほぼ0の場合はこの不具合を疑うこと**
- BudouXの塊マージ規則に「な(る/り/っ/れ/ろ)」(なるの活用形全般)・「べき」・「ない」を追加。さらに**fugashi形態素解析でBudouXの塊境界が単語内部を割っていないか機械的に検査し、割っていれば強制結合する安全装置(`enforce_word_boundaries`)を追加**し、「置いと/いて」のような真の単語内部分断を検出・修正できることを確認(これは個別パターン追加ではなく汎用の安全装置)
- 3163で「卸すのを選択した」(文脈上「堕ろす」の誤変換の疑い、妊娠・治療の話)を発見。機微な内容のため自動置換はせず、用語集の「文脈判断が必要な語」に**CEO本人の確認が必要な項目**として登録した
