`git add <自分の変更ファイルのみ>` を明示的に指定しても、その直後の `git commit` は
「今addしたファイルだけ」ではなく **その時点のインデックス全体** をコミットする。
Country Cards対戦システム修正(2026-09-14)で実際に発生:
自分は3ファイルだけ `git add` したのに、`git commit` の結果を見ると
無関係な4ファイル(別の並行セッションが進めていたtrivia関連の修正)が
一緒にコミットされていた。原因は、commitを打つ直前に別セッションが
自分の変更を先に `git add` 済みで、インデックスに既に乗っていたため。

**Why:** 複数セッション(Windows/Mac 2台運用、または同一マシンでの並行セッション)が
同じ作業ディレクトリを触っている時間帯があり得る。`git add` はインデックスに
「追加」するだけで「自分の分だけの一時的なコミット範囲」を作るものではないため、
自分の意図と無関係に他者のstage済み変更が混入しうる。

**How to apply:**
- コミット直前に必ず `git status --short` でステージ済み(先頭列がスペースでない行)を
  自分が意図したファイルだけかどうか確認する。addした直後に一呼吸置かず即commitしない
- 万一混入したまま `git commit` してしまっても、まだpushしていなければ
  `git reset --soft HEAD~1` → `git reset HEAD -- <混入したファイル>` で
  安全に分離できる(混入ファイルの中身はworking treeに残ったまま、他セッションの
  作業を壊さずに済む)。push済みなら独断で歴史を書き換えず秘書に相談する
- [[concurrent-commit-during-task]](秘書のgit add -Aによる巻き込み)とは逆方向の
  事故だが、根っこの教訓は同じ:「今この瞬間のインデックスの中身」を過信しないこと
