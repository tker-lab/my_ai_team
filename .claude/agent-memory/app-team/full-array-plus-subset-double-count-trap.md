CountryCardsの`CardDatabase.swift`で発見した実例:JSON全体を読み込んだ`cards`配列(北朝鮮GDPの特別カードも含めた全1,923件)と、そこから`isSpecial`条件で抜き出した`specialCards`(1件)を両方プロパティとして保持していた。合計を出す`totalCardCountIncludingSpecial`が`cards.count + specialCards.count`という式になっており、`cards`が既に特別カードを含んでいるため1923+1=1924と二重カウントしていた。

**症状の見え方**:同じアプリ内の別画面(ホーム画面は`cards.count`だけを直接使用)は正しい数字(1923)を表示するのに、別の画面(プロフィール画面、`totalCardCountIncludingSpecial`経由)だけ+1された数字になる、という「画面によって合計が食い違う」形で気づいた。単体の画面だけ見ていると「まあこんなものか」で見逃しやすい。

**Why**: ストア提出用スクリーンショット撮影中、複数画面を横並びで確認したことで「1923」と「1924」の食い違いに気づけた。単一の画面だけ確認していたら発見できなかった可能性が高い。このバグはCrownTier(王冠)の完全制覇judge(金の王冠の閾値)にも使われており、実害として「全カード集めても金の王冠に到達できない」という機能的な問題につながっていた。

**How to apply**: 「全件配列」と「そこから抜き出した部分集合」を両方プロパティに持つ設計を見た時は、合計を出す式が`全件.count + 部分集合.count`になっていないか必ず疑う(全件が部分集合を含んでいるなら二重カウント)。複数画面で同じ合計値を出している機能を確認する時は、1画面だけでなく横断して数字を突き合わせると、この種の食い違いに気づきやすい。他アプリ(離乳食管理アプリ等、集計・進捗表示を持つアプリ全般)でも同種の設計をする時に注意する価値がある。
