CountryCards(国カードバトル)のチェック工程(2026-09-13、致命的指摘①②の再チェック)で発見。

`GachaOddsView`は「10連(30枚)の最後の1枚:SSR以上確定」という1つのセクションを、
GachaHomeView(全ガチャ共通の入り口)とIAPGachaView(¥100購入画面)の両方から
リンクしている。しかし実際のロジックでは:
- ¥100のIAP10連 → 30枚目はSSR以上確定(このセクションの記載通り)
- ダブりポイントの10連(100pt) → 30枚目は**SR以上確定**(SSRより緩い保証)

の2種類があり、決定文書(app_team_country_cards.mdの「ダブりカードのポイント化」)
でも意図的に区別されていた。確率テーブル自体(GachaEngine.swift)は正しく
作り分けられていたが、表示画面側が「10連」を一括りにしていたため、ポイント
ガチャのユーザーには不正確な保証内容を見せてしまう状態になっていた。

**Why:** 確率表示画面はApp Store審査ガイドライン3.1.1(購入前の確率開示)対応の
ために作られる重い責任を持つ画面だが、「複数の入手手段(無料/ポイント/課金)が
同じ確率テーブルの一部を共有しつつ、まとめ買いの保証だけ手段ごとに違う」設計だと、
実装側は各ViewModelで正しく作り分けていても、表示側だけが手段の違いを
意識せず1画面に統合してしまいやすい。

**How to apply:** 今後ガチャ・カードコレクション系アプリで確率表示画面を作る/
チェックする際は、「表示している数字がどの入手手段(無料/広告/対戦報酬/ポイント/
課金)にも共通して当てはまるか」を、まとめ買いの保証(最終1枚のレア度確定など)
について特に確認する。共通でないなら手段ごとにセクションを分けるか、
「この保証は¥100購入時のみ」のような注記を明示する。
